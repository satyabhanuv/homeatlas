# v2.7.11 QA Runbook — Scalable Scraping

_Auto-discovery + federal aggregators + sitemap crawler. Replaces v2.7.10's hand-guessed URLs. Run these steps after deploying the Worker._

---

## What v2.7.11 ships

Three scalable mechanisms — none require per-source URL knowledge:

1. **iCal auto-discovery** — given a domain (`sanjoseca.gov`), the Worker fetches the home page, scans `<link rel="alternate" type="text/calendar">` tags, and probes common paths (`/events.ics`, `/calendar.ics`, `/events/feed.ics`, `/events/ical`, `/calendar/ical.ics`, `/events/rss.ics`, `/events/feed`, `/calendar/feed`, `/api/calendar.ics`, `/ical`). Discovered feeds auto-registered per state/metro.
2. **Federal aggregators** — NPS Events API (uses `NPS_KEY`, per-park by state) and USDA Farmers Markets (state-name query, geocoded).
3. **Sitemap crawler** — fetches `/sitemap.xml` + `/sitemap_index.xml` + `/sitemap-events.xml` + `/sitemaps/sitemap.xml`, recurses one level, filters URLs matching `/event`, `/events/`, `/programs/`, `/calendar/`, `/happening`, `/whats-on` (overridable), and scrapes schema.org JSON-LD from each.

**New endpoint:** `/api/events-discover?domain=X.gov` — preview what a domain exposes before adding it to the registry.

**Registry format now supports** `type: "discover" | "sitemap" | "federal" | "schema_org" | "ical"`.

## QA Step 2: Preview discovery for one city (no state changes)

Open: `https://nearnity.com/api/events-discover?domain=sanjoseca.gov`

**Expected response shape:**
```json
{
  "domain": "sanjoseca.gov",
  "feeds": [
    { "type": "ical", "url": "https://sanjoseca.gov/...", "discovered_via": "link-alternate-calendar" | "path-probe-content-type" }
  ],
  "error": null,
  "diag": { "home_status": 200, "attempts": { "probes": [...] } }
}
```

**Pass:** `feeds` array has ≥1 entry OR `diag.attempts.probes` shows all probes returned 404 (which means the city genuinely has no iCal — that's fine, we'll fall back to sitemap crawl for that domain).

**Fail:** `home_status` is not 200 or 3xx → the city home page blocks bots. We may need to switch that entry to sitemap type.

Repeat for `sf.gov`, `oaklandca.gov`, `nyc.gov`, `boston.gov`. At least 2 out of 5 should surface an iCal feed for the mechanism to be worthwhile.

## QA Step 4: Run California events ingest

`https://nearnity.com/api/admin/events-ingest?state=CA&admin_token=YOUR_TOKEN`

**This takes ~30-90 seconds.** Fetches USDA farmers markets for California, NPS events for California parks, auto-discovers iCal feeds for 12 CA cities, sitemap-crawls PCFMA.

**Expected response shape:**
```json
{
  "state": "CA",
  "started_at": "2026-07-17T...",
  "sources": {
    "usda_farmers_markets": { "type": "federal", "fetched": >100, "error": null },
    "nps_events":           { "type": "federal", "fetched": >5,   "error": null },
    "sanjose_gov":          { "type": "discover", "fetched": ?, "diag": { "discovered": [...] } },
    "sf_gov":               { "type": "discover", "fetched": ?, "diag": { "discovered": [...] } },
    ...
    "pcfma_sitemap":        { "type": "sitemap",  "fetched": ?, "diag": { "sitemap_urls_tried": [...] } }
  },
  "total_events": ?,
  "geocoded_events": ?
}
```

**Pass criteria:**
- `usda_farmers_markets.fetched` ≥ 100 (CA has hundreds of markets)
- `nps_events.fetched` ≥ 5 (Yosemite/Sequoia/Redwood NPS events)
- At least 4 of the 12 CA `discover` sources return `fetched > 0` (some city sites won't have iCal — that's fine as long as several do)
- `pcfma_sitemap` either returns events OR its diag shows the sitemap URLs it tried and their statuses (so you can adjust the sitemap URL if none of the guesses hit)
- `total_events` ≥ 150
- `geocoded_events / total_events` ≥ 0.8

**Fail cases + fixes:**
- If `usda_farmers_markets` returns 0 → check `error` field. USDA endpoint schema drifts occasionally; I'll add another retry path.
- If ALL `discover` sources return 0 discovered feeds → the User-Agent header may be being blocked; we'll switch to Googlebot UA in v2.7.11.1.
- If `nps_events` returns "NPS_KEY not configured" → set the secret in Cloudflare dashboard.
