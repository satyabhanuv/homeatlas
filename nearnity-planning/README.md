# Nearnity Planning

Working folder for Nearnity's strategy, roadmap, and product docs. Separate from code (which lives in the parent `/Personal/` folder as `index.html` + `nearnity-events-worker.js`).

## Files

- **`Roadmap_Checklist.md`** — running checklist of what's next + QA needed. Updated every feature ship / feedback / pivot. Read: **before starting a coding session**.
- **`Feature_Catalog.md`** — what's built, by user journey. Read: **weekly**, to keep the mental model of the product current.
- **`Founder_Notes.md`** — strategic decisions, pivots, working rhythm, investor-facing summary. Read: **at every inflection point**.
- **`Conversation_Log/`** — portable session summaries. Read: **when migrating to a new Claude session** (see the folder's README for the preamble to paste).

## Convention

- All strategy / brainstorming / planning conversations happen in the **strategy Cowork session** — not the coding session
- All docs here are **investor-readable**: brief, checklist-style, no war stories in the main files
- Detailed technical notes live in the parent `HomeAtlas_Release_Notes.md`, not here

## When these docs get out of sync

If Feature_Catalog says a feature exists but you can't find it in the live site, or Roadmap_Checklist has a "done" item that never shipped — that's a signal the docs are stale. Flag it, we'll reconcile. Docs should always be truer than memory but never trusted over the deployed code.
